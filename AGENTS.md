# Правила работы в workspace

## Вход и приоритеты

- Пользователь — **арбуз**. Сотрудничать честно, без лести и холодности. Предпочтения — `ABOUT.md`.
- После восстановления контекста читать `NOW.md`: это единственное место текущего статуса и следующего шага. Затем открывать указанные там материалы задачи. Не перечитывать всю историю служебных документов на каждом шаге.
- Перед художественной работой обязательны **актуальные прямые решения автора**, передача предыдущей главы, нужные источники и сцены. Краткое состояние/поиск/QA не заменяют полного чтения нужного текста. Границы чтения записывать честно.
- Проект: `projects/shards-of-the-abyss/`. Прямые решения: `canon/author-decisions-2026-09.md`; действующие версии: `drafts/README.md`; передача текущей главы — из NOW. Сентябрьская библия и внешние резюме не перекрывают прямых ответов автора.
- Различать прямой ответ, редакторское решение и неподтверждённую гипотезу. Похвала главы не утверждает все будущие решения. Канон книги — не биография автора; не сохранять психологические выводы о нём как факты.

## Git и сохранность

- **Никогда `git merge`, слияние PR, смена/создание веток.** Только `arena/01a08101-workspace`; push только `git push origin arena/01a08101-workspace`.
- Законченную работу коммитить и пушить. Отдельным последующим вызовом проверить ветку, remote=HEAD и чистоту дерева. Git сохраняет файлы, не весь чат.
- Внешний репозиторий не менять. `book/` (397 файлов) и `reference/continuation-5246612/` (39 файлов) — неизменяемые источники. Архивные редакции сохранять; правки прозы должны быть осознанно ограничены задачей.
- **Глобальный `* -diff` сохранять.** Не выводить накопительный patch и не запускать `--text` на весь репозиторий. Для проверки пробелов/точного сравнения — `git diff --text --check` или scoped diff только известных текстовых файлов.
- Не применять reset/rebase/force-push/удаление истории, sparse-checkout, LFS-миграцию или смену базы сессии ради уменьшения Diff. Не удалять чат, исходники или `.git`.
- Ранее дважды возвращались старые ref/index при целых опубликованных файлах. Это не установленная причина зависаний. При повторе **остановить запись и staging**, отдельно сравнить HEAD/remote/дерево/локальные правки. Не повторять прежнее восстановление автоматически и не стирать новые изменения.
- Скрипты прежних редактур могут быть неидемпотентны. Не запускать повторно `edits_*.py`, уже исполненные `.cache/ch22-v3/` и `.cache/ch23-v3/refine.py`/`package.py`.

## Редактура и выдача

- Перед/во время очередной редактуры **один содержательный пакет через `ask_user`**, затем писать. Не повторять уже отвеченные вопросы и не просить ещё разрешение на исполнение. Существенные будущие развилки обсуждать, не закреплять произвольно.
- Делегирована глубокая перестройка сцен/диалогов с сохранением сути и последствий. Беречь любимое начало первой главы; не перестраивать его без отдельной необходимости и разговора. Не заменять работу массовыми фильтрами, нормами или механическим сокращением.
- Нужны прожитые события/переживания, ясные предметы реплик и причинность. «Хотят в долг» без конкретного действия — пример неясности, не готовая шутка для возврата. Исправленная Агнис/Кайр/вечер с Тенью — уроки, не обязательные шаблоны.
- Тёмное фэнтези: не смягчать жесть и последствия, но и не превращать всех в жестоких людей. Избегать шаблона «не …, а …»/«это не …, это …» и слова «костяшки» с его формами в новой прозе; править контекстуально. Исторические цитаты и импорты сохранять.
- **Каждая глава/редакция: полный читаемый файл и две точные пары «было / стало» прямо в чате.** Для первого прохода база — сентябрьский источник, для повторного — предыдущая выданная версия. Цитаты проверять по файлам; не сочинять третью редакцию для сравнения. GitHub Diff не заменяет выдачу.
- Техническая QA подтверждает только перечисленные проверки, не литературное качество. Не торопиться, не экономить на нужном чтении и работе над прозой.

## Критические напоминания; подробности — в каноне и передаче

- Райгар всегда в закрытом шлеме **и броне**, почти молчит; еда/питьё вне наблюдения, без придуманной биографии/физиологии. Агнис действует собственной силой другого порядка **без последствий для неё**, не подчинена Тавии/Тальму; не придумывать цену, предел или гарантированное спасение.
- Сёстры важнее всего друг другу. Помощь Агнис безусловна; отказ Сильвии от Арклайта сложнее благодарности гильдии. Запястная смертельная метка — не срок полевого заказа. Тайна создания Агнис неизвестна сёстрам/Тени; изучение обеих не равно созданию обеих.
- Герра только через культуру. Союз Свободных Дверей отменён. Правила порталов брать из прямых решений. Не превращать внешние пересказы в авторский канон.

## Малошумный процесс

- `AGENTS.md` — устойчивые правила, **не журнал каждой главы**. `NOW.md` — краткая текущая передача. `drafts/README.md` — один реестр актуальных версий; остальные README ссылаются на него. Полная история остаётся в Git/проектных журналах.
- Не обновлять 8–10 документов ради одного повторённого статуса. Для главы нужны проза, точные сравнения, одна содержательная передача с чтением/решениями/проверками и короткая QA при необходимости. Другие файлы менять только при реальном изменении канона, структуры или указателя.
- Независимые операции объединять; художественное чтение выводить ограниченными **необрезанными** порциями. В чат не печатать полные деревья, гигантские JSON и повторные логи. Краткий итог проверок достаточен; важные ошибки не скрывать.
- Временные результаты — `.cache/`, зависимости/генерации не в Git; `.cache` не гарантирует сохранность между восстановлениями. Незаменимые решения и доказательства хранить в компактных отслеживаемых материалах. Не делать полный дублирующий backup при каждой главе.
- Не запускать серверы/watchers ради чтения Markdown. Не делать частые повторные сетевые опросы и полный аудит всех файлов после каждой мелкой правки. Полная проверка источников — на выдаче/при подозрении на повреждение.
- Быстрая диагностика: `python tools/workspace_health.py`. Подробности/границы — `docs/arena-optimization-2026-09-12.md`. Пользователь уже пробовал браузеры, кэш, VPN, выход из аккаунта и поддержку без результата; не предлагать это по кругу.
