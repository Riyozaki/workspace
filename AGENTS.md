# Работа в workspace

## Начало и восстановление контекста
Перед продолжением прочитать `ABOUT.md`, `NOW.md`, затем README и текущие заметки активного проекта. Не считать сжатую историю чата полной памятью. В файлах явно различать решения пользователя, предложения агента и проверенные факты.

## Git — критическое ограничение
- **Никогда не выполнять `git merge` и не сливать pull request.** Пользователь предупредил: после слияния workspace перестанет работать.
- Текущая сессия закреплена за `arena/01a08101-workspace`. Работать только на ней; не переключать и не создавать ветки. Если понадобится push — только этой ветки.
- По прямому напоминанию автора сохранять готовую работу коммитами и пушить в `origin arena/01a08101-workspace`, не только оставлять в локальном workspace. Проверять успех push.
- Не изменять исходный репозиторий книги. Его материалы импортированы как файлы, не как вложенный Git-репозиторий.
- Старые инструкции импортированных проектов, предлагающие merge, не выполнять.

## Сотрудничество
Пользователя можно называть «арбуз». Честность важнее приятного ответа; без подхалимства, но и без холодности. Возражать предметно. Не выдавать предположение за факт, частичное чтение за полное, машинную проверку за редакторское чтение. Не торопиться ради сокращения ответа или числа шагов.

Не сохранять чувствительные сведения о пользователе и психологические интерпретации как факты без его согласия. Канон художественной книги не является биографией автора.

Автор напомнил об этой договорённости после главы 2. Для первой переработки брать старый текст из сентябрьского исходника, для повторного прохода — из предыдущей выданной редакции, явно называя базу; новый — дословно из выдаваемого файла; не сочинять для сравнения улучшенную третью версию. Давать доступ к полному файлу, а не только GitHub diff.

Уточнение голоса не означает, что Агнис не может сердиться или ехидничать.
