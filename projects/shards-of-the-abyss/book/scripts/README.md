# Scripts

## `style_guard.py` (v2)

Жёсткий автоматический guard художественной прозы.

### Что проверяет

**1. Лексика** — запрещённые конструкции и маркеры
- `не X, а Y` и все варианты, включая тире и разнесение по предложениям;
- мусорный словарь (`костяшки`, `уголки губ`, `нечто`, `в этот момент` и др.);
- псевдотелесная абстракция (`пришла голова`, `вернулся воздух`);
- метатекстовые метафоры.

**2. Ритм** — главная категория, добавлена в v2
- `STACCATO_GLOBAL` — средняя длина предложения наррации и доля коротких;
- `STACCATO_WINDOW` — локальный рубленый участок;
- `NOMINATIVE_CHAIN` — 3+ безглагольных предложения подряд;
- `ANAPHORA_RUN` — 3+ коротких фразы с одинаковым зачином.

**3. Самоповтор**
- `MONOTONE_DIALOGUE_TAG` — однообразная атрибуция диалога;
- `SELF_DUPLICATE` — дословный повтор предложения в файле;
- `--cross` — дословные совпадения между главами.

**4. Форма**
- одиночные слова-абзацы, плотность `будто` / `словно`.

### Нормы

Откалиброваны по старому черновику арки 1 (`90-archive/manuscript-drafts/arc-01-v4-combined-v2026-07.md`):

- средняя длина предложения наррации: **7,6 слова**;
- доля предложений ≤4 слов: **20%**.

Тревога с 34%, брак с 42%.

Это **нижняя граница**, а не цель. Для новой прозы ориентир выше: средняя длина 8–9 слов. Верхнего порога guard не проверяет — за длинные периоды он не ругается.

### Запуск

```bash
python3 scripts/style_guard.py 03-manuscript/arc-01/ch-01.md
```

Несколько файлов с проверкой пересечений:

```bash
python3 scripts/style_guard.py 03-manuscript/arc-01/*.md --cross
```

Только сводка:

```bash
python3 scripts/style_guard.py <файл> --quiet
```

### Правило

Если guard находит `BLOCKER`, текст нельзя показывать как готовый.

### Важно

`blockers: 0` означает «нет известных дефектов», а не «текст хорош». Guard — последний технический слой, он не заменяет чтение. Проверка троек и ритма эвристическая: она намеренно строгая и требует ручного подтверждения.

## `knowledge_check.py`

Проверка непрерывности знания POV.

### Зачем

Ловит дефект, невидимый для `style_guard`: персонаж использует факт раньше, чем узнаёт его.

Реальный пример из главы 6:

> Правое бедро отзывалось тупо и ровно, потому что **я двенадцать дней пролежала на нём**.

Фраза стояла за три тысячи знаков до того, как целительница назвала срок.

Такие дефекты не ловит стилевой фильтр — каждая фраза правильная. Их не видит и автор при вычитке: он знает факт и не замечает, что герой ещё нет.

### Что проверяет

**Автоматически:**
- первое упоминание ключевых фактов: сроки, названия, имена персонажей, ранги, метка;
- латиница в русском тексте.

**По запросу:**
```bash
python3 scripts/knowledge_check.py <файл> --fact "двенадцат" --learned "— Двенадцать дней."
```
Сравнивает позицию первого упоминания с позицией узнавания и сообщает о нарушении.

### Запуск

```bash
python3 scripts/knowledge_check.py 03-manuscript/arc-02/ch-07.md
```

### Важно

Скрипт **показывает, где искать**, а решение принимает человек. Определить автоматически, знает ли герой факт, невозможно.

## `continuity_check.py`

Детектор **дефекта второго называния** (`02-writing-system/SKILL-writing-craft.md` §13).

### Зачем

Ловит класс ошибок, невидимый для всех остальных скриптов: каждая отдельная фраза
написана правильно, но противоречит другой фразе, стоящей за тысячу строк отсюда.

Реальные примеры из глав 1–2, прошедших `style_guard`, `voice_drift`, `canon_check`
и приёмку автора:

> ch-01: «Пирог был **с луком и рыбой**» → ch-02: «**капуста** осела, тесто взялось»
> ch-01: «Полтора года. До перевода на второй курс» → ch-02: «У Хельги я **четыре года** снимала с плиты»
> ch-01: «вчерашний **я не дочертил**» — мужской род у героини-женщины

Механизм один: деталь, называемая второй раз, не вспоминается, а сочиняется заново
из того же смыслового поля. Поэтому второй вариант всегда правдоподобен и почти
никогда не тождественен первому.

### Что проверяет

**Жёсткое** (почти без ложных срабатываний):

- `POV_GENDER` — глагол мужского рода при «я» в наррации; POV книги женский;
- `INDIRECT` — сдвиг лица в косвенной речи: «Я сказала, что извините»;
- `NAME_VARIANTS` — имена-двойники: Бондарная / Бочарная, Ирсаль / Ирсанна;
- `GLUED` — слитно-раздельно: «наощупь».

**Списки для чтения** (решает человек):

- `DURATION` — разные сроки при одном имени;
- `NGRAM` — формулы, повторяющиеся между главами;
- `REFLECTION` — абзацы «Я поняла / поймала себя»: проверить, не должны ли стоять выше;
- `TIMELINE` — часы сцены подряд, чтобы увидеть время, идущее назад.
- `UNSOURCED` — точное время в наррации, которого POV не мог измерить (SKILL §3.3): «через двадцать две минуты» при том, что часов у Сильвии нет. Оценки («минут десять», «две-три секунды», «около получаса») и числа рядом со счётом не срабатывают. На каждое срабатывание ответить: чем героиня это измерила.

### Запуск

```bash
python3 scripts/continuity_check.py 03-manuscript/arc-01/ch-01.md
python3 scripts/continuity_check.py --all
python3 scripts/continuity_check.py --all --quiet   # без списков для чтения
```

Выписать все упоминания переходящего предмета — обязательный ручной шаг §13.4:

```bash
python3 scripts/continuity_check.py --object пирог 03-manuscript/arc-01/*.md
```

### Важно

Скрипт запускается **последним**, по готовой главе (фаза 2в). Совмещать с письмом
нельзя: дефект второго называния приходит именно там, где текст живой, и проверка
во время письма даёт стерильный текст.

Двух подвидов дефекта скрипт не видит вовсе — **задвоенный персонаж** (один человек
в двух не связанных историях) и **разъехавшийся предмет** (начинка пирога). Для них
существует только чтение и `--object`.
