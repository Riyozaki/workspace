# BRAINSTORM — «Studio» (собственная реализация, аналог OBS Studio)

Ограничения среды: нет дисплея (X11/Wayland), нет веб-камеры и звуковых устройств, нет системного ffmpeg.
Поэтому захват экрана/камеры/микрофона в этой среде НЕ проверяем — это явно отмечаем в отчёте.

## Идеи (20)
1. Сцены с независимым набором источников и переключением одной кнопкой/клавишей (паритет с OBS).
2. Источники: цвет, изображение, текст, видеофайл (декодирование через ffmpeg) — базовый набор.
3. Трансформации источника (позиция, размер, видимость) и z-порядок с кнопками вверх/вниз.
4. Undo/Redo для всех правок сцены (UX: безопасные эксперименты).
5. Горячие клавиши с проверкой конфликтов при назначении (UX).
6. Запись в файл (mp4/h264, webm/vp9) через ffmpeg с плавным завершением (финализация контейнера).
7. Стрим на RTMP-сервер через тот же конвейер (паритет).
8. Понятные состояния ошибок: ffmpeg не найден, неверный путь, нет места, падение энкодера — текст вместо падения.
9. Сохранение/загрузка проекта в JSON с валидацией и миграцией версии схемы.
10. Предпросмотр кадра в браузере (JPEG) и статистика: FPS, пропущенные кадры, время кадра.
11. Фиксированный тактовый генератор кадров с компенсацией дрейфа и учётом «пропущенных» кадров.
12. Кэш декодированных изображений (раньше — читались с диска каждый кадр) — замер до/после.
13. Пропуск перерисовки слоёв, которые не изменились (dirty-флаг) — замер.
14. Автоматические дефолты: разрешение и FPS по умолчанию 1280x720@30, папка записи, имя файла с датой.
15. Типизация через JSDoc + `checkJs` (качество кода без сборки).
16. Тесты: модель, компоновщик (пиксели), хоткеи, построение аргументов ffmpeg, сохранение.
17. Защита от потери данных: предупреждение о несохранённом проекте.
18. Доступность: клавиатурная навигация, aria-метки, контраст, статус через aria-live.
19. Ограничение частоты команд (debounce ползунков), чтобы не спамить сервер.
20. Документация: README с запуском, архитектура, известные ограничения.
