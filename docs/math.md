# Математика метода

## 1. FLOPs на инференсе

Для плотного MLP `784→W1→W2→10` (ReLU не меняет порядок величины, bias и argmax пренебрежимы):

```
F(W1,W2) = 2·(784·W1 + W1·W2 + W2·10)   [FLOPs/sample]
```

Baseline `W1=W2=1024`: `F_b = 2·(802 816 + 1 048 576 + 10 240) = 3 723 264`.
Студенты:

| W1×W2 | FLOPs/sample | `F_b / F_s` [РАСЧЁТ] | параметры | память fp32 |
|---|---|---|---|---|
| 96×64 | 164 096 | **22.69×** | 81 802 | 327 КБ |
| 128×64 | 218 368 | **17.05×** | 108 618 | 434 КБ |
| 160×96 | 283 520 | **13.13×** | 142 026 | 568 КБ |
| 192×128 | 352 768 | **10.55×** | 173 738 | 695 КБ |
| 224×160 | 426 112 | 8.74× | 206 362 | 825 КБ |
| teacher | 3 723 264 | 1× | 1 861 632 | 7.45 МБ |

## 2. Закон Амдала для сквозного пайплайна

Пайплайн: `uint8 batch → (нормализация|каст) → forward → argmax`.
Пусть `t_pre` — общий (одинаковый для обеих моделей) препроцессинг, `t_b`, `t_s` — время forward.

```
S = (t_b + t_pre) / (t_s + t_pre)
```

Отсюда потолок при `t_s → 0`: `S_max = 1 + t_b/t_pre`, и он **не** равен `F_b/F_s`.
Именно поэтому headline-число — измеренное, а FLOPs-отношение приводится отдельно как расчётное.

Для пайплайна P2 (нормализация вложена в веса) `t_pre` = только каст `uint8→float32`
(≈ 0.8 МБ на 1024 изображения; bandwidth-bound), что делает `t_pre` малым.

## 3. Почему ускорение зависит от batch (арифметическая интенсивность)

Веса baseline: 7.45 МБ. При batch `B`:

```
AI(B) = F·B / (4·params)  [FLOP/byte]
```

Для baseline `AI(B) ≈ B·3.72e6 / 7.45e6 ≈ 0.5·B`. Точка перегиба (ridge) для 2 vCPU:
`P_peak / BW ≈ 187 GFLOPS / 20 GB/s ≈ 9.4 FLOP/byte` ⇒ `B* ≈ 19`.
При `B < 19` baseline memory/latency-bound, и выигрыш от уменьшения FLOPs **не** реализуется;
при `B ≫ 19` — compute-bound, и ускорение приближается к FLOPs-отношению (с поправкой на
эффективность малых GEMM). Это объясняет, почему мы репортим три режима: 1, 256, 1024.

## 4. Дистилляция: функция потерь и почему она сохраняет качество

```
L = α·CE(y, p_s) + (1−α)·T²·KL(softmax(z_t/T) ‖ softmax(z_s/T)),  α=0.5, T=4
```

Градиент по логитам студента (используется в коде):

```
∂L/∂z_s = [α·(p_s − y) + (1−α)·T·(p_s^T − q^T)] / N
```

Множитель `T²` в loss компенсирует масштаб градиента `1/T` от softmax с температурой, поэтому
вклад KD не затухает при больших `T`. Soft-targets учителя несут информацию о сходстве классов
(«тёмное знание»), которая действует как регуляризатор для узкого студента: эмпирически это
обычно даёт +0.2–1.0 pp относительно обучения на hard labels при том же бюджете
[ПРЕДПОЛОЖЕНИЕ, проверяется ablation'ом `distill_scratch` vs `hard_scratch`].

## 5. Прунинг: критерий и что он оптимизирует

Для нейрона `j` слоя 1 храним `s_j = ||W₂[j, :]||₂` (L2-норма исходящих весов). Оставляем top-W1.
Это стандартный критерий «важности по исходящим весам»; он не оптимален, но дёшев
(`O(W1·W2)` операций) и не требует данных. После срезки весов студент инициализируется
функцией учителя, ограниченной на подпространство: `f_s(x) = f_t(x)_{|keep}` ровно
(до fine-tune ошибка = только вклад удалённых нейронов).

Оценка ошибки от удаления: если `a_j` — активация нейрона `j`, вклад в логиты `a_j·W₂[j,:]`;
удаление вносит ошибку `||a_j·W₂[j,:]||`. При нормировке на единичную дисперсию активаций
относительная ошибка логитов ≈ `sqrt(Σ_{j∉keep} ||W₂[j,:]||²) / sqrt(Σ_j ||W₂[j,:]||²)`
[РАСЧЁТ, приближение]. Fine-tune компенсирует эту ошибку.

## 6. Стоимость обучения

Метод: `T_teacher + T_soft + T_student`, где `T_soft` — один forward учителя по train-сету.
Baseline: `T_teacher`. Отношение стоимости обучения:

```
r_train = (T_teacher + T_soft + T_student) / T_teacher
```

Оно **больше 1** (см. измерения в отчёте): метод ускоряет инференс, а не обучение.
Это ограничение зафиксировано явно.

## 7. Память

Инференс хранит только студента: `4·params` байт. Для (160×96) — 568 КБ против 7.45 МБ (13.1× меньше).
Пиковая память обучения метода выше baseline на размер soft-targets: `55 000 × 10 × 4 = 2.2 МБ`.
