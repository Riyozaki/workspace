Старые тексты этих документов остались **дословно в Git**, без нового дублирующего архива в рабочем дереве: `git show 44bfc5a:AGENTS.md`, `git show 44bfc5a:NOW.md` и аналогично для README. Полные канонические решения, редакторские передачи и журналы не переписывались. Перед художественной работой читать их обязательно по задаче; экономия — на дублировании, не на знании книги.

Это механизм сворачивания таких файлов **на GitHub**, не команда интерфейсу Arena; документы и файлы не исчезают. Поведение атрибута описано GitHub. - `.gitignore` теперь не допускает обычное случайное добавление зависимостей, сборок и сырых HAR/профилей браузера. Ни один ранее отслеживаемый файл не попадает под новые исключения. Нужные материалы не удалялись и не выводились из Git.
- Не вводились сомнительные `.arenaignore` или скрытые настройки: подтверждённого механизма исключить ими дерево/историю этой сессии не найдено.

### Быстрее и безопаснее проверять

Добавлен [tools/workspace_health.py](../tools/workspace_health.py), без зависимостей и сервера:

```bash
python tools/workspace_health.py
# После законченных commit/push, отдельным вызовом:
python tools/workspace_health.py --remote --require-clean
```

Он выводит несколько строк: ветка/HEAD, объём файлов, свободный диск, скорость status/numstat, действие `-diff`. Не печатает полный patch, не чинит ref/index, не делает fetch/commit/push и не трогает историю. Git запускается с `--no-optional-locks`. Сеть используется только при явном `--remote`; каждый subprocess ограничен 25 секундами. Ошибка не маскируется под успешную диагностику.

Для проверки сохранности по базе:

```bash
python tools/workspace_health.py --base COMMIT --verify-base \
  --allow-changed NOW.md --json > .cache/health.json
```

Список разрешённых изменений задаётся явно под задачу. Проверяются содержимое и тип файлов по Git blob ID **независимо от подавления diff**; удаление базового файла не разрешает даже allowlist. Новые файлы не входят в эту проверку сохранности и требуют отдельного просмотра перед staging. Скрипт не сертифицирует текст, все права доступа или интерфейс Arena.

Восемь локальных тестов проверяют SHA1/SHA256 blob, Unicode/переносы в путях, сохранность, изменения, запрещённое удаление, неизвестный тип и несовпадение symlink. Отдельно проверены ненулевые exit-коды при неверной базе, неразрешённых изменениях и грязном дереве с `--require-clean`.

## 3. Изменение нашего процесса

1. **Один источник текущего статуса — NOW.** AGENTS не дополняется летописью каждой главы; README не пересказывают канон.
2. Для новой главы — проза, дословные сравнения, одна полноценная передача с чтением/решениями/проверками, компактная QA по необходимости. Отдельный дневник операций — только когда действительно полезен. Канон и план арки обновлять по существу, не ради одинакового уведомления в 8–10 файлах.
3. Не вызывать сотни отдельных `git show` при каждой мелкой правке: проверка содержимого по дереву Git и хешам делает ту же техническую задачу одним чтением дерева. Полная проверка источников — на выдаче или при подозрении на повреждение.
4. Независимые операции объединять; логи/машинные таблицы не дублировать в чат. Художественное чтение остаётся полным, порции вывода — ограниченными и необрезанными.
5. Автор по-прежнему получает **целую главу и две точные пары в чате**. Не превращать оптимизацию в урезание прозы, отсутствие вопросов или спешку.
6. Промежуточное — в `.cache`, важное — в компактных отслеживаемых файлах. `.cache` не является надёжным долговременным хранилищем. Не добавлять полный архив книги после каждой главы.
7. Одна законченная порция работы — commit/push и отдельная проверка. Не плодить commits ради имитации прогресса; при длительной работе сохранять настоящий законченный этап. Никакого merge.

## 4. Что нашлось в официальных материалах

- Arena документирует панель с режимами **«last turn» / «full branch»**. Поэтому, если панель всё-таки нужна, режим последнего хода — более узкая область просмотра; если не нужна — держать её закрытой. Статья не обещает, что закрытие отменяет фоновые запросы, и не даёт агенту API отключения панели. Мы этот переключатель за пользователя не меняли. [3](https://arena.ai/blog/coding-in-agent-mode)
- Arena признаёт **известный баг бесконечной генерации**. Это подтверждение существования класса проблемы, **не диагноз именно этой сессии**. Большинство приведённых там бытовых обходов автор уже испробовал; рекомендацию нового чата здесь не исполняем. [3](https://help.arena.ai/articles/8691588590-troubleshooting-infinite-generation)
- В Agent Mode предусмотрено **сжатие контекста**. Статья говорит о меньшей вероятности достижения лимита, не гарантирует бесконечную сессию и не утверждает, что сжатие облегчает отрисовку всей истории браузером. Явное сообщение о лимите отличается от медленной загрузки. [1](https://help.arena.ai/articles/3975292349-arena-troubleshooting-session-token-limits)
- На момент чтения официальная страница статуса показывала **fully operational**. Это не исключает частный сбой и не объясняет предыдущие зависания; календарь страницы частично динамический. [3](https://status.arena.ai/)
- GitHub рекомендует небольшие репозитории, в идеале менее 1 ГБ; наш порядок объёма значительно меньше. Нет признака, что мы упёрлись в описанный размерный предел GitHub. [1](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

Поиск также выдавал «Agent Arena» из Qwen Code и другие одноимённые проекты. Их настройки таймаутов/worktree к Arena.ai не переносились. Надёжного публичного способа обнулить накопительный diff или удалить старые tool-карточки **в существующем чате без потери истории** в просмотренных материалах не нашлось.

## 5. Что реально можно сделать со стороны автора

Не обязательный чек-лист и не ещё один круг поддержки:

- **Не пользоваться Diff для чтения книги.** [Прямая читательская страница на GitHub в нашей ветке](https://github.com/Riyozaki/workspace/blob/arena%2F01a08101-workspace/projects/shards-of-the-abyss/drafts/README.md) позволяет открыть нужную главу отдельно от накопленной истории Arena. Это обход тяжёлого экрана, не ремонт чата. Ветка `main` не обновлялась — открывать именно ссылку на рабочую ветку.
- Если Diff нужен, попробовать документированный «last turn», а не «full branch». Не обещаю, что это прекратит фоновые вычисления. [3](https://arena.ai/blog/coding-in-agent-mode)
- Если после этих изменений зависание повторится и будет желание установить его тип: достаточно **одного** наблюдения DevTools → Network/Timing во время сбоя. Для самого медленного запроса — тип, статус и длительности ожидания/загрузки; без cookies, Authorization, тел запросов и полных URL с идентификаторами. Если запрос завершился, а интерфейс ещё не реагирует, это повод отдельно смотреть загрузку главного потока в Performance, а не снова чистить кэш. Это диагностические ориентиры, не доказательство причины; долгий открытый streaming-запрос сам по себе нормален.
- При очевидно зависшей генерации без прогресса доступная кнопка Stop описана самой Arena. Она прерывает работу: не нажимать только потому, что чтение/написание главы занимает время. После остановки можно продолжить с сохранённых файлов, сначала проверив фактическое состояние. [3](https://help.arena.ai/articles/8691588590-troubleshooting-infinite-generation)

**Не присылать сырой HAR и не коммитить его:** репозиторий публичный; сетевые записи могут содержать авторизацию и приватный текст. Сейчас дополнительных действий от автора для сохранения нашей работы не требуется.

## 6. Что намеренно не делалось

- Не удалялись архивы, PDF, исходники, главы или чат; не заменялись файлы заглушками.
- Не делались sparse-checkout, submodule/LFS-миграция, перепаковка/обрезка истории, смена ветки, main, базового коммита сессии, force-push или merge.
- Не отключались GitHub Actions/Issues/Wiki/безопасность/коннектор: связи этих настроек с задержкой не установлено.
- Не ставились расширения/пользовательские скрипты, не подменялись запросы Arena, не менялись cookies/localStorage и не вызывались недокументированные API.
- Не запускались новые серверы и автоматический фоновый мониторинг, не очищались нужные следы редактур ради 140 КБ.

Удаление старых файлов из нынешнего дерева само по себе не удалило бы их из истории. Добавление в `.gitignore` не скрывает уже отслеживаемые файлы; это профилактика новых артефактов, не магическая очистка UI.
