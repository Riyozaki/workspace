# Brainstorm: full cold RBF-SVM inference on real Fashion-MNIST

All gains in this document are **РАССЧИТАНО under ПРЕДПОЛОЖЕНО conditions**, not measured results. Chosen task is generic dense RBF multiclass inference, not Cartesian/separable GP; every support vector is retained unless explicitly stated otherwise. Baseline/model/quality are frozen in protocol before optimization. Native libsvm, its two-thread public API variant, and an available ONNX SVM runtime are reference candidates; baseline selection is performed before optimized code/results.

Let Q be query count, S support vectors, D=784 pixels, C=10 classes. Model arithmetic includes Q*S dot products and exponentials, plus 45 pairwise decisions and voting. Cold total T=T_import+T_read+T_preprocess+T_kernel+T_vote+T_output.

| # | Idea and hypothesis | Mathematical gain estimate (calculated, not measured) | Risk / decision |
|---|---|---|---|
| 1 | Batch RBF dot products using BLAS-3, not many BLAS-1 dot products | Arithmetic remains ~2QSD; SV reads fall from ~8QSD bytes to ~8SD*ceil(Q/B). If bandwidth-limited, kernel-only bound ~B; whole speedup 1/((1-f)+f/s). | GEMM overhead/exp becomes dominant. Implement after baseline. |
| 2 | Float32 GEMM and float64 norms/decision accumulation | At most ~2x compute and memory improvement vs float64; system gain <=1/((1-f)+f/2). | Cancellation near boundary can change labels; frozen accuracy/agreement gates, no weaker tolerances. Implement as separate candidate. |
| 3 | Cache-aware chunking of queries and support-vector-contiguous layout | Working kernel matrix 8BS (or 4BS) bytes rather than 8QS; fewer page/cache misses, possible 1–3x kernel gain, no guaranteed number. | Tiny blocks waste BLAS; huge ones exceed 4 GB. Fixed validation-only block choices. |
| 4 | Compact inference-only model + NumPy-only startup | If startup/import fraction p is eliminated, theoretical cap 1/(1-p); a large model still costs O(SD) to read. | Conversion must be disclosed; scope is pre-trained inference, not training+inference. Export once alongside baseline artifacts; additionally report conversion cost and non-amortized cost. |
| 5 | Two-thread libsvm chunked prediction | <=2x component gain, often bandwidth <2x. | This is a strong baseline improvement, not claimed as optimized-method novelty. Include before method. |
| 6 | Ready ONNX SVMClassifier CPU runtime | Potential SIMD/float32 speed benefit vs libsvm; no fixed estimate without implementation. | Install may fail, precision/serialization may differ. Attempt installation, measure before custom method; never invent result. |
| 7 | Fused native/SIMD exp + decision reduction | Remove temporary kernel matrix read/write: save ~2*w*B*S bytes per batch. | Existing NumPy exp already optimized; compilation/startup and correctness risks. Conditional implementation only. |
| 8 | Exact constant-feature elimination | If only d<=D coordinates vary across every SV, dot work ratio D/d; constant coordinates contribute analytically to distance. | Must inspect train/model only, not select test features; potential no constant features. Diagnostic only unless useful. |
| 9 | Nyström/low-rank approximation | Kernel work QS D -> QrD + QrS or changed classifier; gain depends on r/S. | Changes model/quality, cost to prepare model must be included; not first choice with strict tolerance. Not implemented unless time/validation supports it. |
| 10 | Support-vector pruning using coefficient/kernel error bounds | Work S/s_remaining; 50x demands keeping <=2% SVs. | Likely unacceptable decision error on clothing images; exact gates unchanged. Reject unless certified bounds. |
| 11 | Distill into small neural/linear model | Inference O(Q D H) vs O(QSD), nominal S/H. | Training and teacher generation costly, accuracy not guaranteed; no neural framework installed. Reject for primary study. |
| 12 | Int8 exact/quantized GEMM on originally uint8 pixels | SIMD throughput/memory may improve 2–4x over fp32; integer squared distances can be exact before exp. | Need an actual optimized integer GEMM backend and overflow checks; NumPy integer matmul is not optimized BLAS. Investigate, do not claim theoretical improvement. |
| 13 | Certified adaptive precision | Use fp32 first, recompute uncertain label votes in fp64. Cost T32 + p*T64; gain vs all-fp64 <=T64/(T32+p*T64). | Need sound error bounds, not heuristic hiding test disagreements. May use conservative correction, not change quality gate. |

Selection: implement (1), (2)+(3), and optionally (4), at most three integrated systems. First measure the strong ready references. Seek 50x, but accept a smaller honest result. No data duplication to inflate inference, no cached answers, no hidden/organizer score is claimed. Validation selects among predeclared systems/blocks; holdout remains untouched until code selection is frozen.
