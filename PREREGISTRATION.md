## 1. Task and data

- Dataset: **Fashion-MNIST** (Xiao et al., 2017), official 60k train / 10k test split, 28×28 grayscale,
  10 classes. Files obtained from the official `zalandoresearch/fashion-mnist` GitHub repository.
- Split: first 55,000 official train images = train; last 5,000 = validation; official 10,000 test images
  = test. The test set is touched **once**, after all architecture/hyperparameter choices are frozen.
- Input pipeline: flatten 784, cast uint8→float32, standardize with train mean/std. No augmentation.
- This is a real, public, fixed benchmark, not synthetic data generated by the method.

## 2. Quality metric and tolerance (primary)

- Primary metric: **top-1 accuracy on the 10,000-image official test set**.
- Tolerance: the method is "iso-quality" iff the **mean paired accuracy gap**
  `gap = acc_baseline − acc_method` is **≤ 1.00 percentage point (pp)**, and the **upper bound of the
  two-sided 95% confidence interval of the mean paired gap** is also **≤ 1.00 pp**.
  (Paired by seed: for each seed the student is distilled from that seed's teacher and both are evaluated
  on the identical test set.)
- Secondary reported metrics (not success criteria): macro-F1, per-class accuracy, expected calibration
  error (ECE, 15 bins). They are reported for transparency, never used to redefine success.
- A stricter 0.50 pp check is also reported, labelled as secondary.

## 3. Baseline

- Baseline = the **full-size teacher MLP** that a practitioner would deploy without our method:
  `784 → 1024 (ReLU, dropout) → 1024 (ReLU, dropout) → 10`, softmax cross-entropy.
- Training recipe: AdamW (decoupled weight decay 1e-4), batch 128, cosine LR decay to 1% of peak,
  15 epochs, He initialization. A **small pre-registered grid selected on validation only**:
  peak LR ∈ {5e-4, 1e-3}, dropout ∈ {0.0, 0.2}. The best validation configuration is frozen and used
  for every baseline seed. No test data is used for this choice.
- Baseline must be a genuinely trained, converged model — not a deliberately weakened one. We will also
  report the published MLP range for Fashion-MNIST (~88–90% test accuracy) as a sanity check.

## 4. Method (pre-registered)

**DistillPrune** — latency-aware structured distillation:

1. Train the teacher (baseline) once per seed.
2. Compute teacher soft targets on the 55k training set at temperature `T = 4`.
3. Rank hidden neurons by the L2 norm of their outgoing weight vector. Keep the top `w1` neurons in
   layer 1 and top `w2` in layer 2; slice the weight matrices to form a dense student.
4. Fine-tune the student with the combined loss
   `L = α·CE(y, p) + (1−α)·T²·KL(q_T ‖ p_T)`, `α = 0.5`, `T = 4`,
   AdamW, batch 128, 30 epochs, cosine LR.
5. Inference is the dense student only; no teacher call, no cascade, no caching, no test-time tricks.

Student width `(w1, w2)` is chosen from the pre-registered grid
`{(96,64), (128,64), (160,96), (192,128), (224,160)}` using **validation accuracy only**, under the
constraint that the analytical inference-FLOPs reduction versus the baseline is **≥ 10×**.
Selection rule: smallest width whose validation accuracy is within 0.50 pp of the teacher's validation
accuracy; if none qualifies, the widest width that still meets ≥10× (highest validation accuracy).
The test set is not used for this choice.

Controls (same student architecture, same budget):
- **HardScratch**: student trained from random init on hard labels only (no teacher).
- **DistillScratch**: student trained from random init with the distillation loss.
- **DistillPrune** (ours): pruned teacher initialization + distillation fine-tuning.
These ablations isolate the contributions; the primary method is DistillPrune.

## 5. Speedup definition (measured, end-to-end)

- Pipeline timed: in-memory uint8 image batch → cast/normalize (per batch) → full forward pass →
  argmax. Disk I/O is excluded identically for both models; data are already in RAM.
- Hardware/software: same machine, same process settings (`OMP_NUM_THREADS=2`,
  `OPENBLAS_NUM_THREADS=2`), float32, NumPy BLAS. Batch sizes **1, 256, 1024** are reported.
- Protocol: 3 warm-up passes, then ≥20 timed passes (batch 1: 2,000 single queries, 3 warm-ups),
  median and IQR reported. Headline number = **batch-1024 end-to-end throughput speedup**
  `T_baseline / T_method`.
- Analytical FLOPs ratio is reported separately and explicitly labelled **CALCULATED**, never as
  measured. Amdahl decomposition is reported: shared preprocessing/postprocessing time and its effect
  on the achievable speedup.
- No comparison against a naive Python-loop implementation. Both baseline and method use the exact same
  NumPy forward code; only layer sizes differ.

## 6. Runs and statistics

- Seeds: **0, 1, 2, 3** (4 seeds) for the final comparison. Each seed trains baseline → soft targets →
  all student variants. Same seed controls initialization and batch order where applicable.
- Report mean, standard deviation, and 95% CI (Student-t, df = 3) of accuracy and of the paired gap.
- A run is never discarded. Failed/diverged runs are reported.
- All raw numbers go to `results/*.csv` / `results/runs.jsonl`; logs are not curated.

## 7. Decision rule (fixed now)

The claim "≈10× faster without quality loss" is made **only if both** hold:
1. measured batch-1024 end-to-end speedup ≥ 10.0×, and
2. the quality criterion in §2 holds (mean and 95% CI upper bound of the paired gap ≤ 1.00 pp).

If speedup is ≥10× but the gap criterion fails, we report the failure and the best iso-quality speedup
(largest measured speedup among variants satisfying §2), without redefining the tolerance.
If speedup is <10×, we report the measured value and do not round it up.
Theoretical/calculated numbers are never presented as measured.

## 8. Known risks fixed in advance

- Small MLP students may lose >1 pp on Fashion-MNIST; distillation may not close the gap.
- CPU wall-clock speedup can be lower than the FLOPs ratio because of per-batch Python/BLAS overhead;
  this is exactly why the headline metric is measured, not calculated.
- Fashion-MNIST MLPs are not transformers; external validity to large language/vision models is not
  claimed and will be listed as a limitation.
